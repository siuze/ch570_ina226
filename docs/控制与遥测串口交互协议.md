# 控制与遥测串口交互协议

- 控制与遥测串口通常是Dongle插入PC后COM端口号较大的那个；
- 在“总线已报告设备描述”中可看到值为“CH570 Sensor Control”
- 波特率115200
- 使用 ASCII 文本进行交互
- 每条命令和每条响应都以 `\r\n` 结束；USB CDC 一次读操作可能包含半行或多行，开发者必须先按 `\r\n` 分行，再按行首标签解析。

## 1. 命令下发与响应总表

命令区分大小写，参数使用 ASCII 十进制，除明确标为十六进制的 CRC32 外不使用二进制参数。每条命令都应等待响应后再发送下一条会改变设备状态的命令。

| 命令 | 功能描述 | 成功响应 | 失败响应/说明 |
|---|---|---|---|
| `CMD:RST` | 让 Probe 对下游目标 MCU 产生一次正常复位 | `[OK] Target Reset` | 无线事务失败时随后出现 `[ERR] ...` |
| `CMD:BOOT` | 让 Probe 将下游 MCU 置于 ROM 下载/Bootloader 模式 | `[OK] Enter Bootloader` | 无线事务失败时随后出现 `[ERR] ...` |
| `CMD:SWAP` | 交换 Probe 下游 UART 的 RX/TX 引脚映射 | `[OK] Target UART Swapped` | 无额外错误文本 |
| `CMD:RATE=N` | 设置 INA226 采样上报周期，N 为十进制毫秒 | `[OK] Rate Set` | `[ERR] Invalid Rate (10-1000ms)` |
| `CMD:SHUNT=N` | 设置分流电阻值，N 为十进制微欧姆 | `[OK] Shunt Set` | `[ERR] Invalid Shunt (>0uOhm)` |
| `CMD:AVG=N` | 设置 INA226 内部平均次数 | `[OK] Avg Set` | `[ERR] Invalid Avg (1/4/16/64/128/256/512/1024)` |
| `CMD:FSC=N` | 设置电流满量程，N 为十进制 mA | `[OK] FSC Set` | `[ERR] Invalid FSC (1-20000mA)` |
| `CMD:LINKLED=N` | 设置 Dongle 链路灯最大亮度 | `[OK] Link LED Set` | `[ERR] Invalid Link LED (10%-100%)` |
| `CMD:BLE=N` | 设置 Probe BLE 广播频率，N 为 Hz | `[OK] BLE Rate Set` | `[ERR] Invalid BLE rate (1-20Hz)` |
| `CMD:SAVE` | 将当前配置写入 Dongle 和 Probe 的 Flash | `[OK] Saved to Flash` | 无线事务失败时随后出现 `[ERR] ...` |
| `CMD:CFG?` | 查询当前采样、串口、LED 和 BLE 配置 | 一行 `[CFG] ...` | 无 |
| `CMD:VER?` | 查询 Dongle 及已连接 Probe 的固件版本 | `[VER] Dongle: ...`，随后 `[VER] Probe: ...` | 未绑定时 `[VER] Probe: <not connected>` |
| `CMD:LEDTEST=...` | 选择 LED 自检模式 | `[OK] LEDTEST set` | `[ERR] LEDTEST expects NORMAL/GPIO_ON/GPIO_OFF/PWM/PWM_NO_RF/PWM8_NO_RF` |
| `CMD:RFTEST=N` | 测试 2.4GHz 链路有效吞吐和往返延迟 | 先 `[OK] RFTEST started`，结束再返回 `[RFTEST] ...` | `[ERR] RF link not ready` 或 `[ERR] RFTEST duration 100-5000ms` |
| `CMD:DFU` | 擦除 Dongle 应用首扇区并进入 WCH ROM ISP | `[OK] DFU reset to bootloader; replug USB if not detected, then flash via WCHISPTool` | `[ERR] ISP erase failed` |
| `CMD:PROBE_DFU` | 请求 Probe 擦除应用首扇区并进入 WCH ROM ISP | 先 `[OK] Probe ISP requested`，确认后 `[OK] Probe entering ISP; connect its UART to WCHISPTool` | `[ERR] Probe not ready` |
| `CMD:FW_START=<size>,<crc32>` | 开始 Dongle 固件备用区更新 | 见第 8 节 | `[ERR] FW size invalid ...` 等 |
| `CMD:FW_DATA=<offset>,<hex>` | 向 Dongle 备用区写入一段固件数据 | 见第 8 节 | `[ERR] FW_DATA invalid` 或 `[ERR] Flash write failed` |
| `CMD:FW_FINISH` / `CMD:FW_ABORT` | 校验并应用或取消 Dongle 更新 | 见第 8 节 | CRC、状态或超时错误 |
| `CMD:PROBE_FW_START/DATA/FINISH/ABORT` | 通过 2.4GHz 更新或取消 Probe 固件 | 见第 9 节 | `[ERR] Probe ...` |
| 其他命令 | 无对应功能 | 无 | `[ERR] Unknown Command` |

`[OK]` 和 `[ERR]` 是统一的命令结果标签；`[INA]`、`[RSSI]`、`[LINK]`、`[VER]`、`[CFG]` 和 `[RFTEST]` 是数据、状态或异步结果标签。

## 2. 自发上报 INA 采样数据 `[INA]`

Dongle 周期输出：

```text
[INA] V:5.012V, I:123.125mA, P:617.16mW\r\n
```

格式定义：

```text
[INA] V:<float>V, I:<float>mA, P:<float>mW\r\n
```

- 三个数值都是 ASCII 十进制浮点数，不是二进制浮点；
- `V` 小数点后最多 3 位，单位 V；
- `I` 可带负号，小数点后最多 3 位，单位 mA；
- `P` 小数点后最多 2 位，单位 mW；
- 上位机应按完整行匹配 `[INA] V:%fV, I:%fmA, P:%fmW`；
- 实际量化精度由 INA226 raw 决定：母线 1.25 mV/LSB，20 mOhm 分流电阻下电流 0.125 mA/LSB。

## 3. 自发上报 2.4 GHz RSSI `[RSSI]`

```text
[RSSI] -68 dBm\r\n
```

`-68` 是带符号十进制整数，表示最近有效 RF 包的接收信号强度。RSSI 是低频状态数据，不能单独作为链路心跳；链路存活应以 `[INA]` 连续数据和 `[LINK]` 事件共同判断。

## 4. 自发上报 连接事件 `[LINK]`

绑定成功：

```text
[LINK] Bound! Ch=11, Addr=0x6EA416B6\r\n
```

断开并回到默认发现状态：

```text
[LINK] Disconnected, listening on Ch 17\r\n
```

`Ch` 为十进制信道号，`Addr` 为带 `0x` 的 8 位十六进制访问地址。连接事件是异步消息，不对应某一个 COM2 命令。

## 5. 版本查询响应 `[VER]`

`CMD:VER?` 返回 Dongle 版本；若当前已绑定，会再通过无线请求 Probe 版本：

```text
[VER] Dongle: 2026-10-07 rXX\r\n
[VER] Probe:  2026-10-07 rXX\r\n
```

未绑定时返回：

```text
[VER] Probe:  <not connected>\r\n
```

版本内容是 ASCII 文本，解析时按 `[VER] ` 后的设备名和版本字符串分割，不应依赖版本长度。

## 6. 配置查询响应 `[CFG]`

`CMD:CFG?` 返回：

```text
[CFG] RATE=100ms, FSC=20000mA, AVG=64, SHUNT=20000uOhm, SWAP=0, LINKLED=255, BLE=4Hz\r\n
```

字段均为 ASCII 十进制整数：`RATE` 是毫秒，`FSC` 是 mA，`AVG` 是 INA226 平均次数，`SHUNT` 是 uOhm，`SWAP` 是 0/1，`LINKLED` 是 0~255 占空上限，`BLE` 是 Hz。配置命令会更新 Dongle 并同步采样配置到 Probe，同时写入两端配置 Flash。

## 7. 命令结果 `[OK]` / `[ERR]`

### 7.1 普通控制

```text
CMD:RST\r\n
[OK] Target Reset\r\n
CMD:BOOT\r\n
[OK] Enter Bootloader\r\n
CMD:RATE=100\r\n
[OK] Rate Set\r\n
```

非法参数只返回一条 `[ERR] ...`，不会改变当前配置。`CMD:CFG?` 和 `CMD:VER?` 还会产生第 5、6 节定义的异步/查询数据行。

### 7.2 RFTEST

`CMD:RFTEST=N` 的 N 是十进制毫秒，范围 100~5000：

```text
[OK] RFTEST started\r\n
[RFTEST] bytes=45056 time=5000ms rate=9011B/s A1280 M840 X4200 P352\r\n
```

结束行字段依次为有效字节数、测试时长、有效速率、平均往返延迟 us、最小延迟 us、最大延迟 us、测试包数。未绑定或参数越界时只返回 `[ERR]`。

## 8. Dongle 固件更新

### 8.1 参数编码

- `size`：**十进制 ASCII 无符号整数**，单位字节，例如 `27292`；
- `crc32`：**十六进制 ASCII 文本**，允许或不允许 `0x` 由当前解析器统一按十六进制读取，推荐不带 `0x`，例如 `A1B2C3D4`；
- `offset`：**十进制 ASCII 无符号整数**，单位字节；
- `hex`：**ASCII 十六进制文本**，每两个字符表示一个固件字节，不是原始二进制，不带空格，例如 `A55A00FF`；
- 每个 `FW_DATA` 最多携带 128 个固件字节，偏移必须 4 字节对齐。

### 8.2 交互

```text
CMD:FW_START=27292,A1B2C3D4\r\n
[OK] FW_START\r\n
CMD:FW_DATA=0,A55A00FF...\r\n
[OK] 128\r\n
CMD:FW_FINISH\r\n
[OK] FW_VERIFIED, APPLYING...\r\n
```

每个 `FW_DATA` 的响应数字是下一个期望偏移，单位为十进制字节。错误包括 `[ERR] FW not started`、`[ERR] FW_DATA invalid`、`[ERR] Flash write failed` 和 `[ERR] CRC mismatch exp=... act=...`。更新期间 COM1、遥测和 RF 普通业务暂停，完成后 Dongle 复位。

`CMD:FW_ABORT` 返回 `[OK] FW_ABORTED` 并退出更新状态。

## 9. Probe OTA

Probe OTA 的 `size`、`crc32`、`offset` 和 `hex` 编码规则与第 8 节相同，但每个 `PROBE_FW_DATA` 最多 64 个固件字节：

```text
CMD:PROBE_FW_START=16332,A1B2C3D4\r\n
[OK] PROBE_FW_START\r\n
CMD:PROBE_FW_DATA=0,A55A00FF...\r\n
[OK] 64\r\n
CMD:PROBE_FW_FINISH\r\n
[OK] PROBE_FW_VERIFIED, APPLYING...\r\n
```

Probe 未连接、无线超时、Flash 写入失败或 CRC 错误时返回 `[ERR] Probe ...`。收到 `APPLYING...` 后应停止发送，等待 Probe 重启并重新绑定。`CMD:PROBE_FW_ABORT` 返回 `[OK] PROBE_FW_ABORTED`。

## 10. 解析顺序

上位机按行读取后，按以下顺序分派：`[INA]`、`[RSSI]`、`[LINK]`、`[VER]`、`[CFG]`、`[RFTEST]`、`[OK]`、`[ERR]`。任何未知标签都应记录到日志，不应当作遥测数据。
