# 上位机详细设计

## 1. 进程和数据流

`app_win` 是 Windows C++/ImGui/DirectX11 程序。UI 线程只读取 `AppState` 并调用 `SerialManager`，不直接操作串口句柄。COM1、COM2 和 BLE 各自有接收线程，固件更新在独立工作线程执行。

```text
COM1 reader ─┐
COM2 reader ─┼─> AppState ─> Dashboard / CSV / charts
BLE scanner ─┘
```

`AppState::TelemetryHistory` 保存最近 15 分钟的原始样本，较早数据压缩为每秒一个趋势点，同时维护统计量和能量积分；`rfTestMutex`、`controlLogMutex`、`com1RxMutex` 分别保护异步结果。COM1/COM2 字节计数使用原子变量，避免 UI 读取时锁住高吞吐透传路径。

## 2. Windows 串口发现

`SerialManager::EnumeratePorts` 使用 SetupAPI `GUID_DEVCLASS_PORTS` 枚举当前存在的 COM 设备，读取：

- `SPDRP_FRIENDLYNAME`：设备管理器显示名；
- `SPDRP_HARDWAREID`：VID/PID 和 USB interface 标识；
- `SPDRP_BUSREPORTEDDEVICEDESC`：USB 总线报告的设备描述；
- 设备注册表 `PortName`：实际 `COMx`。

Dongle `VID_1A86&PID_FE0C` 的 `MI_00` 归入 COM1 透传，`MI_02` 归入 COM2 控制。缺少 MI 标识时才用 `CH570 Wireless UART` / `CH570 Sensor Control` 描述后备识别。列表标签显示 `COMx - Friendly Name（总线设备描述：...）`；`isDongleCOM1` 的预览和下拉项使用蓝色粗体。刷新后按 COM1 Dongle、上次端口名、索引顺序选择。

COM1 打开时保存端口和波特率，并设置 DTR/RTS 控制线；关闭时停止读线程并清空句柄。自动重连只对用户主动打开过的 COM1 生效。COM2 连接后自动发送 `CMD:VER?` 和 `CMD:CFG?`。

## 3. COM1 透传和烧录

COM1 reader 以重叠 I/O 读入任意字节，原样放入接收缓冲，文本模式按换行形成日志，HEX 模式按 16 字节分组显示；TX 直接写串口并累加 `com1TxBytes`。串口终端不解释下游协议，因此 ESP32、STM32、AVR 或自定义 Bootloader 都可使用。

烧录器操作 DTR/RTS 时，Dongle 固件识别 CDC 控制线逻辑状态。Windows 使用分步写入，Linux/macOS 可能使用原子写入：

```text
0 -> 2 -> 3 -> 1 -> 0 : BOOT 事件（Windows classic）
0 -> 3 -> 2 -> 1 -> 0 : BOOT 事件（POSIX atomic）
0 -> 2 -> 0           : RST 事件
```

状态 2 后 500 ms 内必须完成后续匹配；USB 驱动重复发送同一状态不会重复触发。Dongle 将自动复位事件放入独立的两项队列，再通过 RF 下发，因此连续复位事件不会覆盖 COM2 的配置、版本或测速命令。

上位机保持 ESP-IDF 默认 `before=default_reset` 和 stub 流程。DTR/RTS 的事件转换属于下游 MCU 通用功能，ESP32 仅作为测试对象；不要求用户预先发送 `CMD:BOOT`，也不要求 `--before no_reset`。

## 4. COM2 文本解析

接收线程按 CR/LF 分行，未知行仍写控制日志。解析规则如下：

| 行前缀 | 解析动作 |
|---|---|
| `[INA]` | `sscanf("[INA] V:%fV, I:%fmA, P:%fmW")` 读取 V/I/P |
| `[RSSI]` | 更新 RSSI、有效标记和最近时间 |
| `[LINK]` | 写日志并更新绑定/断链显示 |
| `[VER]` | 区分 Dongle/Probe，保存版本字符串 |
| `[CFG]` | 写日志，配置页重新读取时显示 |
| `[OK] RFTEST started` | 开始 RFTEST 状态计时 |
| `[RFTEST]` | 解析 bytes/time/rate/A/M/X/P，完成测试 |
| `[OK]` / `[ERR]` | 写控制日志，升级工作线程据此推进或失败 |

遥测文本的有效位由固件 raw 换算决定：V 显示三位小数但步进为 1.25 mV；I 显示三位小数但 20 mOhm 时步进为 0.125 mA；P 显示两位小数并由 V/I 计算。上位机不会把显示小数位当成传感器精度。

## 5. BLE 扫描和解析

BLE scanner 只接受目标广播地址/服务 UUID `0xFCD2`，从 AD type `0x16` 的小端字段取直接工程量：

```text
02 01 06
08 16 D2 FC PP PP PP PP SS
06 09 43 48 35 37 30
```

`PP` 为 32 位小端打包值：低 17 位为有符号电流码、单位 0.125mA；高 15 位为母线电压码、单位 1.25mV；`SS` 是滚动序号。上位机直接换算电流和电压，再计算功率，不读取或依赖分流电阻。BLE 是无连接广播，不提供可靠传输；Dongle COM2 遥测优先作为连接态数据源。

## 6. 数据平滑和统计

样本按来源、时间戳、V/I/P、RSSI 保存。15 分钟内曲线使用原始采样，超过 15 分钟的曲线历史按每秒一个点保存；CSV 在接收线程记录原始上报值，仪表卡片显示侧取最近三个样本做尖峰抑制，不修改统计和积分。连接状态以 COM2 遥测包为主要心跳，不以低频 RSSI 行判断断线。

Ah/Wh 使用相邻点梯形积分：

```text
Ah += ((I_prev + I_now) / 2 / 1000) * dt / 3600
Wh += ((P_prev + P_now) / 2 / 1000) * dt / 3600
```

内部单位为 Ah/Wh，界面乘 1000 显示 mAh/mWh。`dt<=0` 或 `dt>=10s` 的样本不积分。累加器使用 `long double`，读取时加锁转换为 `double`；首个样本只建立基线，清空波形或双击能量卡会同时重置积分。

## 7. RF 链路诊断

诊断页提供 1/3/5 秒下拉框。点击后设置 `running=true`，记录开始时间并发送 `CMD:RFTEST=N`。Dongle 统计以 `A5 5A` 开头的 128 字节测试帧，Probe 对帧 ACK 并累计 RTT，最后返回：

```text
[RFTEST] bytes=6400 time=5001ms rate=1279B/s A1200 M900 X2400 P50
```

UI 显示有效 KB/s、平均/最小/最大 RTT 和包数。若超过 `N+3000ms` 未收到结果，UI 清除 running 并写入超时日志，允许重新测试。固件侧还会在 500 ms 忙超时后清除丢失测试 ACK 的等待标志，避免测试状态机永久停住。

## 8. OTA 与 ISP 工作流

### Dongle 自更新

更新线程读取镜像，计算 CRC32，发送 `CMD:FW_START=size,crc`。其中 `size` 是十进制字节数，`crc` 是不带 `0x` 的十六进制 ASCII 文本；每个 `CMD:FW_DATA=offset,hex` 的 `offset` 是十进制字节偏移，`hex` 是 ASCII 十六进制文本，不是原始二进制，最多表示 128 个数据字节。每块等待 `[OK] <offset>` 后再发送下一块，最后发送 `CMD:FW_FINISH`。Dongle 在 `0x20000` 备用区完成写入和 CRC 校验后，暂停 RF/透传/遥测，擦写 `0x00000` 运行区并复位。更新期间不允许普通串口流量竞争 Flash。

### Probe 无线 OTA

上位机发送 `CMD:PROBE_FW_START=size,crc`，Dongle 将请求转成 `OTA_OP_START`；Probe 擦除 `0x20000`。随后每块最多 64 字节，Dongle 发送 `OTA_OP_DATA(offset,len,data)`，Probe 校验范围、4 字节对齐并写 Flash 后 ACK。`PROBE_FW_FINISH` 触发 Probe CRC 校验，成功后复制备用区到 `0x00000` 并复位。任何超时或 CRC 错误都可用 `PROBE_FW_ABORT` 结束。

### ISP 恢复

`CMD:DFU` 或 `CMD:PROBE_DFU` 不是普通 OTA：固件擦除地址 `0x00000` 的 4 KiB 启动扇区，软复位后由 WCH ROM ISP 接管。此时 USB/无线应用协议不可用，必须使用 WCHISPTool 物理连接重新烧录。

## 9. UI 页面

- 硬件遥控：RST、BOOT、配置、版本和控制日志；
- 数据串口穿透：COM1 选择、波特率、HEX、发送和 RX/TX 统计；
- 链路功能诊断：BLE 信息、RSSI、RFTEST、INA226 分辨率说明；
- 固件维护：Dongle/Probe 镜像选择、进度、CRC、ISP/OTA 状态。

上位机只在用户点击操作或自动连接时发送命令，不在绘图循环发送控制帧。升级期间界面禁用普通透传和配置按钮，避免状态竞争。
