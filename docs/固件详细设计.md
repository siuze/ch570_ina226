# 固件详细设计

## 1. 工程、启动和内存

工程包含 `RF/RF_Uart`（Probe）和 `RF/RF_UartDongle`（Dongle），运行在 CH570Q 裸机 RISC-V 上，链接 WCH 的 `libCH57xRF.a` 和 `libISP572.a`。两个镜像均从 `0x00000` 运行，备用更新区为 `0x20000`，配置页为 `0x3A000`，备用镜像最大 32 KiB。

Probe 启动顺序为：时钟 100 MHz、SysTick 自由运行、MAX811 控制初始化、PA1 RX LED 上电提示、UART 引脚和 UART 外设、配置加载、INA226、RFRole、RF UART 状态机。PA1 的 3 秒提示发生在 `UART_DefInit`、UART 中断和 `uart_start_receiving` 之前，因此不会接收或转发这段时间的目标 MCU 数据。提示结束后 PA1 回到输入上拉，正常 UART RX LED 活动由外部线路电平体现。

Dongle 启动顺序为：时钟、USB CDC 双接口、配置加载、RFRole、RF UART RX、PA2/PA3 LED 软件 PWM。升级状态会让主循环跳过透传/遥测/LED Poll，避免 Flash 操作被普通业务打断。

最近一次独立构建：Probe Flash 约 17.2 KiB、RAM 11012/12288 B；Dongle RAM 11084/12288 B。RF 回调、Flash 临界区和栈空间不应增加大块临时数组。

## 2. 引脚、电气和串口

Probe PA0 为 TXD、PA1 为 RXD，PA2/PA3 是 INA226 软件 I2C，PA7 是 MAX811/BOOT 控制。UART 支持 `UART_SwapPins`，交换后 PA1 为 TX、PA0 为 RX。UART RX 中断把硬件 FIFO 写入 768 字节环形缓冲，主循环 `UART_RxQuery` 按帧超时或 32 字节阈值取出；RF 数据写入 UART FIFO，UART THR 空中断继续发送。

Dongle COM1 是 USB CDC 透传 FIFO，COM2 是 ASCII 控制命令 FIFO。USB 的 `SET_LINE_CODING` 会更新目标 UART 波特率配置，Probe 收到 `CTRL_OP_SET_CFG`/波特率参数后重新设置 UART 分频。命令行接收 CR/LF 分隔，二进制透传不经过命令解析。

## 3. DTR/RTS 与下游 MCU 控制

Dongle 接收 CDC `SET_CONTROL_LINE_STATE` 的逻辑位（bit0=DTR、bit1=RTS），不直接把 CH340 的低有效电压当作输入。状态机兼容 ESP-IDF/esptool 的分步和原子两种写法：

```text
Windows classic: 0 -> 2 -> 3 -> 1 -> 0  = BOOT
POSIX atomic:    0 -> 3 -> 2 -> 1 -> 0  = BOOT
hard reset:      0 -> 2 -> 0             = RST
```

状态 2 表示 RTS 已断言而 DTR 未断言。进入状态 2 后的匹配窗口为 500 ms；窗口内到达状态 3，或原子序列的状态 1，生成 BOOT；到达状态 0 生成 RST。重复的相同 USB 请求不重复生成事件，串口重新枚举时清空状态。自动复位事件进入 2 项 FIFO，与 COM2 文本命令分开，避免连续复位请求覆盖配置或测速命令。

BOOT 事件通过 `CTRL_OP_BOOT` 无线发送，Probe 的 `MAX811_BootloaderTarget` 先让 PA7 推挽高 5 ms，再推挽低 1500 ms 覆盖 MAX811S 的复位保持窗口，然后推挽高 200 ms 稳定 C106，最后切换为浮空输入。RST 事件通过 `CTRL_OP_RESET` 产生 PA7 高 5 ms、低 20 ms、高 200 ms，最后切换为浮空输入。

PA7 低电平经 D101 将目标 BOOT 拉低，经 C106 把下降沿耦合到 MAX811S MR#。BOOT 释放不能通过永久锁存实现；复位窗口结束后先推挽高电平稳定耦合电容，再浮空，才能同时满足 ROM 下载时序和后续目标板 EN 按键的正常复位。COM1 的 DTR/RTS 逻辑服务于通用下游 MCU 烧录，ESP32 ROM 下载只是验证用例。

## 4. RF 包格式和绑定

所有专有 RF 包使用 4 字节包头：

```text
type:1 | length:1 | seq:1 | resv/credit:1 | payload:length-PKT_DATA_OFFSET
```

普通 RF 负载上限 251 字节，2 Mbps PHY。关键类型：

| 类型 | 含义 |
|---:|---|
| `0x01/0x81` | 绑定请求/响应 |
| `0x02/0x82` | 状态请求/响应 |
| `0x7E/0xFE` | UART 数据/ACK |
| `0x30` | 控制命令 |
| `0x31` | raw 遥测 |
| `0x32` | 控制响应 |
| `0x33` | OTA 响应 |

未绑定双方在默认访问地址、信道 17 上握手。Dongle 生成随机访问地址，工作信道为 `gServerData % 37`，并发送 `bound_rsp_t`：`accessaddr(4)、channel(1)、phy(1)、serverData(2)、interval(2)、timeout(2)`。绑定后双方切换访问地址/信道；超时回到信道 17。`interval=10 ms`，`timeout=100`（10 ms 单位），Dongle 约 2.5 s 无有效包判定断链。

当前没有连续能量扫描；RSSI 只附加在接收包之后。若实现信道协商，应在信道 17 轮询候选 0~36，收集固定窗口的合法包 RSSI、CRC 错误和空闲比例，再把最佳信道写进绑定响应；需要评估首次绑定延迟和 RF 库是否支持无包 RSSI 读取。

## 5. UART 透传协议和流控

Probe `pUartbuf` 保存目标 MCU RX 数据，Dongle `USB_RxQuery` 保存 PC 发往目标的数据。状态请求携带 Probe 可用信用 `resv`；Dongle 只有在信用至少 64 字节时才从 COM1 取数据，单包最多 251 字节。Probe 收到 `PKT_CMD_RSP_STATUS/OPCODE_DATA` 后写入目标 UART，并在 ACK 中继续发送控制或下一批数据。

重复序号不会再次写入 UART，避免 ACK 丢失造成 ESP ROM SLIP 数据重复。忙事务超过 500 ms 会释放当前 RF 事务并重试；正常链路超过约 2.5 s 没有有效包则断链并回到信道 17。

## 6. Raw 遥测协议和计算

为避免把同一 ADC 数据重复编码，当前 `telemetry_pkt_t` 为 5 字节 packed 结构：

```text
int16_t  shunt_raw;   // INA226 0x01，2.5 uV/LSB
uint16_t bus_raw;     // INA226 0x02，1.25 mV/LSB
uint8_t  flags;       // 预留
```

Probe 每次读取 INA226 原始寄存器后只发送这两个 raw 值。Dongle 按已同步的 `g_dongle_cfg.shunt_uohm` 计算：

```text
shunt_uV = shunt_raw * 2.5
current_uA = shunt_raw * 2,500,000 / shunt_uohm
bus_mV = bus_raw * 1.25
power_mW = bus_mV * abs(current_uA) / 1,000,000
```

计算使用 64 位整数并在分母处四舍五入，避免 20 mOhm 以外的分流电阻产生比例错误。Dongle 再格式化 COM2 文本：V 三位小数、I 三位小数、P 两位小数。上位机只解析文本工程值；BLE 传输压缩后的工程量，不再要求扫描端知道分流电阻。

INA226 的 `ina226_data_t` 仍在 Probe 内部保留派生值，供本地 LED、BLE 兼容接口和调试使用；这些派生值不再进入专有 RF 遥测包。

该 5 字节布局是 Probe/Dongle 的协议版本变更，两个端点必须配套升级。仅升级其中一端会导致长度检查或字段解释不一致，不应与旧版固件混用。

## 7. BLE 广播实现

未绑定超过约 1 s 后，Probe 在 37/38/39 信道各发送一次 `ADV_NONCONN_IND`。广播配置为 BLE 1M PHY、访问地址 `0x8E89BED6`、CRC24 `init=0x555555/poly=0x80032D`、硬件白化。

AdvData 为 20 字节以内，Service Data 采用压缩工程量格式：

```text
02 01 06
08 16 D2 FC PP PP PP PP SS
06 09 43 48 35 37 30
```

其中 `PP` 是 32 位小端打包值，低 17 位为有符号 `current_code`（单位 0.125mA，高位符号扩展），高 15 位为 `bus_code`（单位 1.25mV），`SS` 是滚动序号；UUID `0xFCD2` 用小端 `D2 FC`。该格式不暴露 INA226 分流 raw，扫描端无需知道采样电阻。射频发送前保存并恢复专有 RF 的检测寄存器，`g_ble_adv_active` 让链路状态机忽略 BLE burst 的 RF 中断。

## 8. INA226、LED 和连接状态

INA226 使用 PA2/PA3 软件 I2C，配置为连续 shunt+bus、1.1 ms 转换时间、可配置平均次数，默认 64 次。采样周期默认 100 ms，可由 `CMD:RATE` 设置。

Probe 正式版本的 RX LED 上电阶段由 `uart_startup_rx_led` 主动拉低 PA1 3 秒；临时 `--without-UART` 版本在这 3 秒后以 PA1 作为母线电压呼吸灯，档位为 5 V/40%/4 s、9 V/60%/3 s、12 V/80%/2 s、18 V/100%/1 s，电压按最近档位选择。PA0 作为电流大小指示灯，按满量程电流比例渐亮。该临时版本不初始化目标 UART，也不执行串口透传。

Dongle 通信灯的 `g_com1_activity_bytes` 在 COM1 向 Probe 发送或从 Probe 收到有效 UART 数据时增加。LED1 每秒把增量放入 5 个桶，求最近 5 秒总字节数：0 字节为 4 秒呼吸，少量数据在 3 秒到 1 秒之间过渡，达到 1024 B/5 s 为 1 秒呼吸。`RF_bound_Flag` 由绑定响应置位、断链清零；未绑定时 LED1 为 2 Hz 方波闪烁，因此“已绑定”与“有透传流量”是两个独立状态。

电流灯由最近遥测包更新目标占空。超过 5 秒无遥测目标为零，目标值经约 700 ms Q16 一阶低通；定时器约 250 Hz、64 瞬时等级并跨周期分数累加到 12 位有效亮度。两颗 Dongle LED 均为低电平点亮。

## 9. 控制命令和配置持久化

COM2 命令由 Dongle 解析，映射到 `ctrl_cmd_pkt_t`：

```text
opcode:1 | param8:1 | param16:2 | param32:4 |
full_scale_ma:2 | link_led_max_duty:1 | ble_adv_hz:1
```

`CMD:RST`、`CMD:BOOT`、`CMD:SWAP`、`CMD:RFTEST=N`、`CMD:PROBE_DFU` 生成无线控制操作；`CMD:RATE/SHUNT/AVG/FSC/BLE/LINKLED/SAVE` 修改完整配置并可写 Flash。配置结构保存 magic、shunt_uohm、avg_samples、report_interval_ms、full_scale_ma、uart_swapped、link_led_max_duty、ble_adv_hz，地址 `0x3A000`。Dongle 和 Probe 各自保存一份本机配置；Dongle 收到设置后先写自己的配置，再通过无线包同步 Probe。写入前关闭中断、擦除 4 KiB，并把 17 字节 packed 结构填充到 20 字节（4 字节对齐）后写入，避免 Flash API 因长度未对齐而丢失设置。

配置命令先由 Dongle 更新自己的 `g_dongle_cfg` 并写入 Dongle 的 `0x3A000`，随后将同一份 `shunt_uohm/avg_samples/report_interval_ms/full_scale_ma/ble_adv_hz` 放入 `CTRL_OP_SET_CFG` 无线包；Probe 收包后更新 INA226、写入自己的 `0x3A000` 并回到正常采样。`uart_swapped` 和 `link_led_max_duty` 属于 Dongle 本地行为，Probe 不使用这两个字段。

## 10. RFTEST 状态机

`CMD:RFTEST=N` 经 `CTRL_OP_RF_TEST` 启动 Probe 状态 1。Probe 发送 128 字节、前两字节 `A5 5A` 的标记包；Dongle 识别标记后只计数和回 ACK，不进入目标 UART。Probe 根据 ACK 往返时间累计总和、最小值、最大值和包数，时间到达后发送状态 2 最终响应。Dongle 输出：

```text
[RFTEST] bytes=<字节> time=<毫秒>ms rate=<B/s> A<平均us> M<最小us> X<最大us> P<包数>
```

标记 ACK 500 ms 内未到达时，Probe 清除待确认时间戳并继续测试；最终响应超时则释放测试状态。上位机另有请求时长加 3 秒的超时保护。

## 11. OTA、Flash 擦写和 ISP

### Dongle 自更新

`CMD:FW_START=size,crc32` 校验大小后擦除 `0x20000` 备用区；`CMD:FW_DATA=offset,hex` 每块最多 128 字节、偏移 4 字节对齐，写入后返回下一个偏移；`CMD:FW_FINISH` 计算备用区 CRC32。成功后 `FW_SetRfPaused(1)` 关闭 BLEB/BLEL 中断，清空 COM1 FIFO，擦除运行区 `0x00000`，按 256 字节从 `0x20000` 复制回运行区并软复位。

### Probe OTA

`CMD:PROBE_FW_START` 经 `OTA_OP_START` 令 Probe 擦除 `0x20000`；`OTA_OP_DATA` 每块最多 64 字节，检查范围和 4 字节写入对齐；`OTA_OP_FINISH` 对备用区计算 CRC32。成功后 Probe 关闭中断，擦除 `0x00000`，按 256 字节复制备用区，软复位到新镜像。`CMD:PROBE_FW_ABORT` 清除升级状态。

### ISP

`CMD:DFU` 在 Dongle 擦除 `0x00000` 的 4096 字节并 `SYS_ResetExecute()`；空启动扇区使 WCH ROM ISP 接管 USB/UART。`CMD:PROBE_DFU` 由 Probe 收到确认后执行同样动作。ISP 阶段应用固件、RF、USB CDC 和 COM2 均不可用，必须连接 WCHISPTool 物理接口重新烧录。

## 12. 性能约束

RF 包最大 251 字节、PHY 2 Mbps；ESP32 烧录性能还受 UART 波特率、RF 往返、FIFO 信用、stub 压缩、Flash 擦除和校验影响。当前 460800 应用区写入约 31.6 s，115200 约 78.7 s。Probe RAM 余量约 1.3 KiB，新增功能必须复用静态缓冲，禁止在 RF/Flash 临界路径放置大数组或格式化字符串。
