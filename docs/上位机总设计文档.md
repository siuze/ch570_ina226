# CH570 无线串口与电流功耗监测上位机总设计文档

## 1. 文档范围

本文档描述 `CH570_Monitor` Windows 上位机及其配套 Dongle/Probe 固件的功能边界、数据路径、界面行为、控制命令、升级流程和已知限制。上位机使用 C++20、Dear ImGui、ImPlot、Win32 串口 API、Windows C++/WinRT BLE API 和 DirectX 11。

## 2. 系统组成

```text
下游 MCU <-> Probe(CH570) == 2.4G == Dongle(CH570) <-> USB <-> Windows 上位机
                                      |
                                      +--> COM1: 目标 MCU 透传
                                      +--> COM2: 遥测与配置
```

- **Probe**：目标 MCU 串口透传、INA226 电流/电压采样、目标 MCU BOOT/RST 时序、未连接 Dongle 时的 BLE 广播。
- **Dongle**：USB 双 CDC-ACM、2.4G 链路、COM1 透传、COM2 遥测/配置、Probe OTA 转发、两颗状态 LED。
- **上位机**：端口识别、自动重连、遥测解析、曲线和卡片显示、CSV、命令控制、固件维护、BLE 监听和诊断。

## 3. 端口识别与连接

上位机通过 Windows SetupAPI 读取端口的总线设备描述，并显示为 `COMx - 设备描述 (COMx)`。Dongle 的复合 USB 设备按接口区分：

- `MI_00 / COM1`：目标 MCU 透传；
- `MI_02 / COM2`：遥测、配置和升级。

连接流程为刷新端口、自动探测 VID/PID 和接口、打开 COM2、发送 `CMD:VER?` 与 `CMD:CFG?`，再按配置打开 COM1。读取线程把完整行交给解析器，写线程负责命令和透传数据。端口拔出后进入自动重连，重新枚举到相同设备后恢复端口、版本和配置查询。

## 4. 遥测数据链路

COM2 遥测格式为：

```text
[INA] V:5.012V, I:123.125mA, P:617.16mW
```

Probe 端 INA226 原始分辨率为 2.5 uV/LSB 分流电压和 1.25 mV/LSB 母线电压。专有 RF 遥测传输原始寄存器以便 Dongle 按 `SHUNT` 配置恢复工程值；BLE 广播传输压缩后的有符号电流码（0.125 mA/LSB）和母线电压码（1.25 mV/LSB）。上位机解析后统一存储为 V、mA、mW，并写入 `TelemetryHistory` 环形队列。

数据分为两条路径：

1. **原始路径**：曲线、min/max、CSV、容量/能量积分均使用原始采样；
2. **显示路径**：卡片数值取最近三点中值去除单点毛刺，再使用采样时间戳驱动的 0.8 秒 EMA。滤波不受 ImGui 帧率影响。

单位采用回差：电流 1.50 A 进入、1.35 A 返回 mA；电压 2.00 V 进入、1.80 V 返回 mV；功率 1.00 W 进入、0.85 W 返回 mW。大单位仍固定保留 3 位小数。

容量和能量在内部以 Ah/Wh 积分，界面显示 mAh/mWh，使用 6 个数字槽和 3 位小数。异常采样间隔大于 10 秒时不参与积分。

## 5. 实时曲线

曲线支持电流、功率、电压独立开关，时间窗口为 30 秒、1 分钟、2 分钟、5 分钟、10 分钟、30 分钟和 1 小时。曲线不使用卡片滤波值，电压轴根据当前窗口最大值动态扩展，避免电压曲线被固定上限裁掉。

## 6. CSV 导出

启用“导出 CSV”后，在应用目录创建 `csv` 文件夹，按用户选择的 0.1/0.5/1/2/5/10/30/60 秒间隔记录。每小时自动换文件，名称为 `record_YYYYMMDDHHMMSS.csv`。

列定义：

```text
timestamp_ms,time,current_mA,voltage_V,power_mW,capacity_mAh,energy_mWh
```

CSV 保存原始遥测值，不使用卡片显示滤波。文件使用单个 LF 行结束，避免 Windows 文本模式把 CRLF 转换成空白行。

## 7. 串口终端和日志

- COM1 终端支持 ASCII/HEX、波特率设置、发送数据和 `None / \\r\\n / \\n` 换行选项；
- 交互日志和串口日志自动添加 `HH:MM:SS.mmm` 时间标记；
- 日志使用可复制文本区域，长行允许水平滚动；
- 串口活动状态由 COM1 实际收发字节驱动。

## 8. 配置项目

配置页面通过 COM2 命令读写：

| 项目 | 命令 | 默认/范围 |
| --- | --- | --- |
| 遥测周期 | `CMD:RATE=` | 默认 100 ms |
| 满量程电流 | `CMD:FSC=` | 默认 20 A |
| INA226 平均次数 | `CMD:AVG=` | 默认 64 次 |
| 采样电阻 | `CMD:SHUNT=` | 默认 20 mOhm |
| 通信灯亮度上限 | `CMD:LINKLED=` | 10%~100%，内部 26~255 |
| BLE 广播频率 | `CMD:BLE=` | 默认 4 次/s，1~20 次/s |
| 保存 Flash | `CMD:SAVE` | 写入设备配置区 |

下发配置、查询配置、设备重连完成后，界面重新读取实际值，避免只显示本地选择值。

## 9. LED 与 PWM 设计

PA2（电流灯）和 PA3（通信灯）均为低电平点亮，分别连接 CH570 PWM2/PWM3。

硬件 PWM 诊断保留在 `CMD:LEDTEST=PWM/PWM_NO_RF/PWM8_NO_RF` 中；正常产品路径使用 GPIO 软件 PWM。软件 PWM 定时器载波约 250 Hz、64 个瞬时等级，12 位目标占空值的低 6 位通过跨周期分数累加实现，不把定时器中断提高到约 1 MHz。

```c
/* PA2/PWM2 and PA3/PWM3 are the default (NO_ALTERNATE) functions. */
/* Keep PIN_ALTERNATE at its reset value; it is not a PWM route selector. */
PWMX_CLKCfg(8);
PWM_16bit_CycleEnable();
PWMX_16bit_CycleCfg(CH_PWM2 | CH_PWM3, 52083);
PWMX_16bit_ACTOUT(CH_PWM2, duty, Low_Level, ENABLE);
PWMX_16bit_ACTOUT(CH_PWM3, duty, Low_Level, ENABLE);
```

LED 是“VCC→LED→电阻→PA2/PA3”的低电平点亮连接。电流灯目标占空每次遥测到达时经过约 700 ms 一阶低通，超过 5 秒无遥测才归零。通信灯未绑定时为 2 Hz 方波；已绑定后统计 `g_com1_activity_bytes` 最近 5 个一秒桶，0 字节为 4 秒呼吸，达到 1024 B/5 s 为 1 秒呼吸，中间过渡。

## 10. BLE 广播和扫描

Probe 未绑定 Dongle 时使用固定地址 `CA:57:09:1E:A2:26`，在 BLE 37/38/39 三个信道发送 `ADV_NONCONN_IND`，默认 4 次/s。Probe 与 Dongle 建立链路后停止 BLE 广播。

广播服务数据使用 UUID `0xFCD2`，字段为 4 字节小端打包值和滚动序号；打包值低 17 位为有符号电流码（0.125mA/LSB），高 15 位为母线电压码（1.25mV/LSB）。该量化与 20mΩ 采样电阻下 INA226 的原生步进一致，上位机直接计算工程量，不需要同步分流电阻。

Windows 侧使用 `BluetoothLEAdvertisementWatcher`。已经尝试：

- `Active` 扫描；
- `SignalStrengthFilter.SamplingInterval = 20 ms`；
- `OutOfRangeTimeout = 2 s`；
- 增加广播序号并取消按地址/负载的重复抑制。

当前实测 BLE 上位机更新仍可能约 1~2 秒一次。该问题暂不宣称已解决，原因可能在 Windows 蓝牙驱动、适配器扫描调度或系统级广告合并；固件空口默认频率和上位机回调频率不是同一个指标。后续应增加独立空口计数或使用原生 `DeviceIoControl`/专用 BLE 接收器做对照测试。

## 11. 固件维护

固件维护页包含：

- Dongle 进入 ISP：`CMD:DFU`；
- Probe 进入 ISP：`CMD:PROBE_DFU`；
- Dongle 固件下发：COM2 分块发送 HEX，CRC32 校验后写入备用区并切换；
- Probe OTA：Dongle 通过 2.4G 转发分块数据，Probe 校验后切换镜像。

Dongle 和 Probe 备用区均为 `0x20000`，最大镜像 32 KiB；配置页为 `0x3A000`。升级过程中暂停透传、遥测和 RF 中断，镜像先写备用区并计算 CRC32，再按 256 字节复制到 `0x00000` 后复位。进入 ISP 后 USB/无线链路会断开，必须用 WCHISPTool 物理重新烧录。

## 12. BOOT/RST 控制

`CMD:RST` 和 `CMD:BOOT` 由 Probe 产生目标 MCU 的 RST/BOOT 时序。BOOT 进入流程会保持 BOOT 有效，直到下一次 `CMD:RST` 显式释放；复位芯片存在 BOOT 先动作、约 500~900 ms 后 RST 掉电的约束，不能把 BOOT 短按误认为完整启动时序。

## 13. 诊断和验收

验收至少包括：

1. COM1/COM2 自动识别、拔插自动重连和配置回读；
2. 电流/电压原始分辨率、单位回差和卡片抗抖；
3. CSV 无空行、小时分割和原始值精度；
4. PA2/PA3 软件 PWM 约 250 Hz 载波、12 位有效调光，低电平点亮；
5. 未绑定 BLE 广播地址、频率和 payload 校验；
6. Dongle/Probe 固件升级 CRC 校验、掉电保护和失败恢复；
7. `CMD:RST`/`CMD:BOOT` 的 BOOT、RST、EN 时序。
