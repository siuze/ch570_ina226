# 基于 CH570Q 的无线串口调试与电流测量工具

> **参赛赛事**：“沁恒 RISC-V MCU 杯”第 11 届立创电子设计大赛
> **开源协议**：OpenAtom OHL 1.0
> **设计软件**：嘉立创 EDA 专业版
> **主控芯片**：沁恒 CH570Q（RISC-V 内核，DFN-10 3×3 封装）
> **资料依据**：CH570 数据手册

---

## 1. 项目功能介绍

### 1.1 要解决的问题

- **有线串口的限制**：USB-TTL 串口线长度受限，调试工位限制大，也容易缠绕、误触短路。
- **功耗不可见**：普通无线串口只能传输打印信息，无法同时获知目标板的电流 / 电压 / 功率。
- **复位与烧录不便**：ESP32、STM32 等单片机烧录或卡死时需要操作 EN/RST 与 BOOT/GPIO0 引脚；无线串口若引脚不足，仍需到现场按键。
- **TX/RX 反接**：目标板丝印错误或杜邦线反接时需要重新拔插。

### 1.2 功能概述

本项目用一对 CH570Q 构成无线串口链路，并在探针侧加入高侧电流采样与单引脚复位 / 烧录控制：

- **2.4G 无线串口透传**：PC 侧 Dongle 与目标板侧 Probe 之间通过 2.4G 专有射频透传串口数据；PC 侧修改波特率时，Dongle 将配置帧无线下发给 Probe 同步生效。
- **上电自动配对（一碰连）**：Dongle 与 Probe 上电后先在默认频道、默认同步字（访问地址）下握手：Probe 发出绑定请求，Dongle 依据请求中携带的历史绑定 ID（保存于 Flash）或接收信号强度（两端靠近时 RSSI 足够高）决定是否接受；接受后 Dongle 下发本次会话专用的随机访问地址与工作频道，双方切换到该私有地址 / 频道通信，Probe 把绑定信息写入 Flash，下次上电自动重连，无需手动配置。链路超时后双方回到默认频道重新绑定。
- **在线高精度电流 / 电压测量**：Probe 在供电通路中串入 20mΩ 采样电阻，用 INA226 做高侧测量，以 0.125mA（分流满分辨率）和 1.25mV（母线满分辨率）原始精度采样，回传 PC 与广播遥测；功率由上位机直接基于高精度 V×I 实时解算。
- **未连接上位机时自动降级为超紧凑极简 BLE 广播遥测**：Probe 检测到自己未与 Dongle 绑定（持续约 3s）后，自动切换为 BLE 广播信标：在 37/38/39 三个广播信道周期（默认 1s）发送 `ADV_NONCONN_IND` 广播帧。为充分利用 INA226 的硬件物理分辨率并极致精简报文长度，广播载荷仅保留母线电压与采样电流两个物理量，剔除冗余字段与计算项功率（交由上位机实时解算），整包广播有效数据仅 11 字节（较原方案缩减 56%），空中时间仅 ~260µs，极大降低发射功耗与空中冲突；手机与 PC 端在免配对、免连接模式下即可扫描读取。
- **PC 端双虚拟串口（CDC-ACM 复合设备）**：一个 USB 口枚举出两个 COM 口，COM1 用于目标板数据透传与烧录，COM2 用于输出保留 0.125mA 物理分辨率的高精度遥测数据（格式如 `V:5.012V, I:123.125mA, P:617.16mW`）和控制指令输入。
- **单引脚复位与烧录控制**：Probe 仅用 PA7 一个引脚（CH570Q 引脚分给串口和 I2C 后只剩 1 个可用），配合 MAX811S 复位芯片与 RC 微分、二极管隔离网络，分别产生“目标板复位”和“进入 Bootloader”两种时序。
- **TX/RX 软件互换**：串口反接时可通过指令在固件内交换 TX/RX 引脚映射，无需改线。
- **状态指示 LED（共 4 颗）**：
  - Dongle 侧 LED201（PA2）为电流回传指示，亮度随目标板电流大小变化（PWM 调光），收到遥测报文时作心跳闪烁；LED202（PA3）为通信 / 链路状态指示。
  - Probe 侧 LED101（PA0/TXD）、LED102（PA1/RXD）分别为串口发送与接收活动指示，对应线路有数据时微亮点亮。
- **一块 PCB 两种形态**：Dongle 与 Probe 共用同一张 PCB，按区域装配（对方区域的元件不焊接）。

## 4. 硬件部分

### 4.1 总体结构

系统分为 PC 侧 Dongle 与目标板侧 Probe，共用一张 PCB：

```text
[ PC 上位机 ]
     │ USB（USB-A 座 USB201，Dual CDC-ACM：COM1 透传 + COM2 遥测/控制）
     ▼
┌──────────────────────────────────────────────────┐
│ Dongle 端 (CH570Q U1)                             │
│   PA0/PA1 = USB D-/D+（经 U201 ESD 保护）          │
│   PA2 = 电流回传指示 LED（R201 100Ω）              │
│   PA3 = 通信状态指示 LED（R202 1kΩ）               │
│   X1 32MHz 晶振 + E1 PCB 天线                     │
└──────────────────────────────────────────────────┘
                     ▲▼  2.4GHz 无线链路
┌──────────────────────────────────────────────────┐
│ Probe 端 (CH570Q U1)                              │
│   供电：Type-C(USB103) VBUS_IN → R104 20mΩ →       │
│         VBUS_OUT → Type-C(USB104) 供目标板         │
│   采样：INA226 U105 跨接 R104，I2C = PA2(SDA)/PA3(SCL)│
│   串口：PA0 = TXD，PA1 = RXD（排针 H101）          │
│   控制：PA7 → C106 微分 → MAX811S U102 → RST#      │
│         PA7 → D101 → BOOT                         │
│   电源：LDO U101 或 MCU_VCC 经 D102/D103 或到 VCC   │
└──────────────────────────────────────────────────┘
     │
     ▼
[ 目标单片机 ]  VBUS_OUT 供电 / TXD·RXD / RST#(EN) / BOOT(GPIO0)
```

### 4.2 共用核心电路

- **主控 U1（CH570Q）**：pin1 VDD33/VIO33 接 VCC（3.3V），pin2 V5（5V），pin3 PA0、pin4 PA1、pin5 PA7、pin6 PA2、pin7 PA3，pin8/pin9 接晶振，pin10 接天线，pin11(EP) 接地。
- **时钟 X1**：32MHz 四脚晶振（pin1=X32MI、pin3=X32MO、pin2/4=GND），为射频与系统提供时钟。
- **天线 E1**：PCB 倒 F 天线（FR4 走线），接 ANT 与 GND。
- **去耦**：C1（2.2uF）、C2（100nF）并联在 VCC 与 GND 之间。

### 4.3 Dongle 端电路（连接 PC）

- **USB 接口 USB201**：USB-A 母座。VBUS 接 V5（5V 电源），D- 接 PA0，D+ 接 PA1，外壳 / 地接 GND。
- **ESD 保护 U201（PRTR5V0U2X）**：跨接在 PA0/PA1 与 V5、GND 之间，对 USB 数据线做 ESD 与过压保护。
- **指示 LED**：
  - LED201（绿）阳极接 VCC，阴极经 R201（100Ω）接 PA2，作电流回传指示（较亮）。
  - LED202 阳极接 VCC，阴极经 R202（1kΩ）接 PA3，作通信状态指示。
  - 四个 LED（含 Probe 侧两颗）的限流电阻按各自规格书计算，更换 LED 型号时需重新计算。
- **电源装配选项 R203（1.5kΩ）**：位于 V5 与 VCC 之间。Dongle（5V 输入）焊接该电阻；Probe（3.3V 输入）不焊接，使 V5 悬空。
- **去耦 C201（2.2uF）**：接在 V5 与 GND 之间。

### 4.4 Probe 端电路（连接单片机与供电线）

#### (1) 供电通路与防倒灌

- **输入 / 输出**：Type-C 座 USB103 的 VBUS 为 VBUS_IN（外部供电输入）；Type-C 座 USB104 的 VBUS 为 VBUS_OUT（向目标板供电）。两座的 CC/SBU/D± 引脚相互连通作直通。
- **板载 LDO U101（NH6375A33P）**：VIN 接 VBUS_IN，规格标称支持最高 50V 供电电压，VOUT 输出 LDO_VCC（3.3V）。输入侧 C101（2.2uF）+ C102（100nF），输出侧 C103（100nF）+ C104（1uF 钽电容）。按手册要求输出电容不小于 1uF，且慎用 MLCC。
- **双路供电或门**：D102（SS14）由 LDO_VCC 指向 VCC，D103（SS14）由排针引入的 MCU_VCC 指向 VCC。两路 3.3V 经肖特基二极管“或”到 VCC，任一路供电时不会向另一路倒灌。VCC 供 CH570Q 与 INA226。
- **设计约束（原理图注明）**：NH6375A33P 输出能力有限，不用于给下游目标 MCU 供电；但允许 Probe 从下游 MCU 的 3.3V 取电；Probe 不从 USB-A 口取电。
- **引出排针 H101（1x6P 2.54mm）**：1=MCU_VCC、2=TXD(PA0)、3=RXD(PA1)、4=GND、5=RST#、6=BOOT，用于连接目标板。
- **2P 接线座 U106/U107（DB125-2.54-2P）**：U106 引出 VBUS_IN 与 GND，U107 引出 GND 与 VBUS_OUT，便于外接电源或串表。

#### (2) 高侧电流采样（INA226）

- **采样电阻 R104**：20mΩ、3W、2512 封装、1% 精度，串接在 VBUS_IN 与 VBUS_OUT 之间，目标板电流全部流经该电阻。
- **20mΩ 下的量程与分辨率**：INA226 分流电压 ADC 分辨率为 2.5µV/LSB、满量程 ±81.92mV；母线电压分辨率 1.25mV/LSB、满量程 36V。在 20mΩ 采样电阻下：
  - 电流分辨率 = 2.5µV ÷ 20mΩ = **0.125mA/LSB**（125µA）；
  - 最大可测电流 = 81.92mV ÷ 20mΩ ≈ **4.096A**（单向 0~4.1A），即量程上限由 INA226 分流满量程决定（采样电阻 3W 额定对应约 12A，不构成限制）；
  - 配合可配置的硬件均值滤波（默认 16 次）可进一步抑制开关噪声、稳定读数。
- **测量芯片 U105（INA226AIDGSR）**：VIN+ 接 VBUS_IN、VIN- 接 VBUS_OUT，跨接 R104 做高侧测量；VS+ 接 VCC，GND 接地；A0/A1 均接地，I2C 地址为 0x40；ALERT 未接。
- **I2C 总线**：SDA 接 PA2、SCL 接 PA3；R105、R106（各 5.1kΩ）分别将 PA2、PA3 上拉到 VCC。
- **滤波 / 去耦**：C107（100nF）跨接 VBUS_IN 与 VBUS_OUT（采样端滤波），C108（100nF）接 VCC 与 GND（VS+ 去耦）。
- 固件读取 INA226 的母线电压与分流电压寄存器（换算得电流），功率由固件按 `P(mW)=I(mA)×V(mV)/1000` 计算后上报（未使用 INA226 的功率寄存器）。

#### (3) 单引脚复位与烧录控制（MAX811S）

CH570Q 为 10 引脚封装，扣除电源、地、天线与通信脚后仅余 PA7 可用于控制。电路用同一引脚区分“复位”与“进入 Bootloader”：

- **复位逻辑**：PA7 经 C106（100nF）耦合到 MAX811S（U102）的 MR# 端；R101（10kΩ）将 MR# 上拉到 VCC；C105（100nF）为 U102 电源去耦。PA7 输出一个短低脉冲时，脉冲经 C106 耦合把 MR# 拉低，U102 在 RESET#（RST#）上输出一个宽度约 Trp（典型 500ms、最大 900ms）的低电平复位脉冲，送至目标板 EN/RESET。
- **烧录模式控制**：PA7 经 D101（1N4148WS，阳极接 BOOT、阴极接 PA7）连接目标板 BOOT/GPIO0。PA7 拉低时，目标板上拉电阻的电流经 D101 流入 PA7，把 BOOT 拉到低电平；PA7 为高时 D101 截止，不影响 BOOT。
- **防误复位**：目标板自身按下 BOOT 键把 BOOT 拉低时，D101 处于反偏截止状态，PA7 与 MR# 电平不受影响，因此不会触发复位。
- **两种时序**：
  - *正常复位运行*：PA7 输出约 20ms 低脉冲（短于复位释放时间），仅触发 RST# 复位；脉冲结束后 BOOT 已恢复高电平，目标板从 Flash 正常启动。
  - *复位并进入 Bootloader*：PA7 保持低电平约 1100ms（长于 Trp 上限 900ms），使 RST# 释放（上升沿）时 BOOT 仍被拉低，目标板锁存进入 ROM Bootloader。

#### (4) 串口与指示

- **串口**：PA0 = TXD、PA1 = RXD，经 H101 接目标板；固件可通过指令交换两者映射以适配反接。
- **串口活动指示**：LED101 阳极接 VCC、阴极经 R102（10kΩ）接 PA0(TXD)；LED102 阳极接 VCC、阴极经 R103（5.1kΩ）接 PA1(RXD)。串口有数据时对应 LED 微微点亮。

### 4.5 装配说明

- 同一张 PCB 上，Dongle 区域与 Probe 区域互不焊接：做 Dongle 时不焊 Probe 区域元件，做 Probe 时不焊 Dongle 区域元件。
- R203（1.5kΩ）仅 Dongle 焊接；Probe 不焊接以保持 V5 悬空。

## 5. 软件部分

### 5.1 固件构成

CH570Q 内部为 12KB SRAM 与约 240KB Flash。固件为 RISC-V 裸机程序，不使用动态内存分配：

| 固件工程 | 角色 | 说明 |
| --- | --- | --- |
| `RF_Uart` | Probe 端 | 串口透传、INA226 采样（软件 I2C，PA2=SDA/PA3=SCL）、PA7 复位 / 烧录时序、TX/RX 交换、未绑定时降级为 BLE 广播遥测 |
| `RF_UartDongle` | Dongle 端 | USB 双 CDC-ACM、2.4G 收发、波特率同步、遥测上报与指令解析、PA2 PWM 电流指示 |

### 5.2 USB 双 CDC-ACM 复合设备

Dongle 使用 USB IAD（Interface Association Descriptor）复合设备描述符，一次枚举出两组 CDC-ACM：

- **COM1（透传）**：与串口助手、终端、烧录器通信；截获 `SET_LINE_CODING` 请求，将波特率配置帧无线下发给 Probe，实现两侧波特率同步。
- **COM2（遥测与控制）**：上行输出保留 0.125mA 与 1.25mV 物理分辨率的高精度纯文本遥测流（格式为 `V:5.012V, I:123.125mA, P:617.16mW\r\n`，可直连上位机或 VOFA+ 等绘图工具）；下行接收控制指令。

> **两个 COM 口的区分**：设备为 IAD 复合设备，两个功能的硬件 ID 分别含 `MI_00`（COM1）与 `MI_02`（COM2），上位机据此稳定区分；固件另为两个功能设置了独立的 `iFunction`/`iInterface` 字符串（`CH570 Wireless UART` / `CH570 Sensor Control`），在 Linux（`lsusb -v`）下可直接可见。

### 5.3 控制指令（COM2，以 `\r\n` 结尾）

| 指令 | 功能 |
| --- | --- |
| `CMD:RST` | 触发目标板复位（PA7 短脉冲，经 MAX811S 产生复位） |
| `CMD:BOOT` | 触发目标板进入 Bootloader（PA7 长低电平） |
| `CMD:SWAP` | 交换 Probe 端 PA0/PA1 的 TX/RX 映射 |
| `CMD:FSC=` | 设置电流指示 LED 的满偏量程 |
| `CMD:RATE=` | 设置采样上报周期 |
| `CMD:SHUNT=` | 设置采样电阻阻值（默认 20000，即 20mΩ） |
| `CMD:AVG=` | 设置 INA226 硬件均值滤波次数 |
| `CMD:SAVE` | 将配置写入 Flash |
| `CMD:CFG?` | 查询当前配置 |
| `CMD:VER?` | 查询 Dongle 与 Probe 的固件版本 |
| `CMD:DFU` | 令 **Dongle 自身**擦除复位向量并复位进入出厂 ISP Bootloader，便于免拆机二次烧录 |

### 5.4 固件版本查询

两端固件在各自 `rf.h` 中以宏 `FW_VERSION_STR` 定义版本号，格式为 `YYYY-MM-DD rNN`（如 `2026-09-29 r01`），可在编译时用 `-DFW_VERSION_STR=\"...\"` 覆盖。上位机向 COM2 发送 `CMD:VER?` 后：

1. **Dongle** 立即回复自身版本：`[VER] Dongle: 2026-09-29 r01`；
2. 若 Dongle 已与 Probe 绑定，则经 2.4G 链路下发 `CTRL_OP_GET_VER` 控制帧，Probe 用 `PKT_RSP_CTRL` 报文回传版本，Dongle 转发到 COM2：`[VER] Probe:  2026-09-29 r01`；
3. 若未绑定 Probe，则回复 `[VER] Probe:  <not connected>`。

`app_win` 上位机在连接 COM2 后会自动查询版本，并显示在窗口顶部状态栏。

### 5.5 未连接上位机时的极简高精度 BLE 广播降级（Probe）

CH570Q 不含 BLE 协议栈；本模式直接调用 2.4G 射频库的底层发送原语（`RFIP_StartTx`），手工拼装符合 BLE 规范的紧凑型广播帧：

- **帧结构**：前导(1B) + 广播访问地址 `0x8E89BED6`(4B) + PDU(`0x02`=ADV_NONCONN_IND + 长度 17 + AdvA 6B + ADV data 11B) + CRC24(3B)。其中 CRC24（初值 `0x555555`、多项式 `0x80032D`）与按信道白化由射频硬件自动完成；PHY 为 1M、LSB-first。
- **信道**：在 37/38/39（2402/2426/2480MHz）三个广播信道各发一次为一个突发；广播间隔默认 1000ms。
- **极简高分辨率载荷设计**：为彻底释放 INA226 的物理采样极限并极致压缩报文体积，载荷剔除冗余字段与计算项功率，仅传输母线电压与采样电流两个原始维度：
  1. **Flags（3B）**：`0x02, 0x01, 0x04`（LE General Discoverable，BR/EDR 不支持）。
  2. **16-bit Service Data（8B，UUID 0xFCD2）**：
     - 长度字节：`0x07`（7 字节）
     - 类型标志：`0x16`（Service Data - 16-bit UUID）
     - 服务 UUID：`0xD2, 0xFC`（0xFCD2）
     - 采样电流（2B，`int16_t`，小端）：直接映射 INA226 分流电压原始寄存器（20mΩ 下 1 LSB = 2.5µV ÷ 20mΩ = **0.125mA**，即 125µA），量程 ±4096.000mA，零量化截断。
     - 母线电压（2B，`uint16_t`，小端）：直接映射 INA226 母线电压原始寄存器（1 LSB = **1.25mV**），量程 0 ~ 36.000V，零量化截断。
  3. **功率解算**：广播载荷无需冗余传输功率，上位机 / 手机在接收到电压与电流后本地实时解算 `P(mW) = V(mV) × I(mA) ÷ 1000`。
  4. **优势**：整包 ADV 载荷从 25 字节压缩至 11 字节（减少 56%），空中发射时间压缩至 ~260µs，极大降低发射功耗与射频信道碰撞几率。
- **触发与回连**：未绑定持续 `BLE_ADV_DEGRADE_MS`（3s）后开始广播；广播突发之间仍走原有绑定请求流程，Dongle 一出现即恢复专有透传链路，广播自动停止。
- **与专有链路的互斥**：广播突发前后保存 / 恢复专有链路的射频寄存器（`R32_MISC_CTRL`、`PKT_DET_CFG3/4`），并在突发期间置活动标志使链路状态机忽略该次发送中断，避免两套射频配置相互干扰。
- **局限**：广播无连接、无应答、无重传，仅适合低速率遥测；串口透传数据不通过广播传输。

### 5.6 编译与烧录

- **Windows**：用 MounRiver Studio 打开 `RF/RF_Uart` 与 `RF/RF_UartDongle` 工程直接 Build（自带 WCH RISC-V GCC + GNU Make），输出 `RF_Uart.hex` 与 `RF_UartDongle.hex`。
- **Linux**：仓库提供可移植脚本 `tools/build_linux.sh`（使用 xPack riscv-none-elf-gcc，march 不含 WCH 私有 `xw` 扩展），可编译全部源码作语法 / 语义校验。
- 最终链接需要 WCH 专有预编译库 `libCH57xRF.a`（2.4G 协议栈）与 `libISP572.a`（Flash 例程），二者随 WCH CH57x EVT/SDK 分发、不含在本仓库内。
- **烧录工具**：官方 [WCHISPTool](http://www.wch.cn/downloads/WCHISPTool_Setup_exe.html)，支持 USB ISP 与串口 ISP，**无需 WCH-Link/SWD**（RISC-V 版 CH570 不支持 ARM-SWD，SWD 仅 CH578M/579M 的 ARM 核有）。
- **CH570Q 的 ISP 引脚**：USB ISP = `PA0(D-)/PA1(D+)`；UART ISP = `PA0(RX)/PA1(TX)`。Dongle 侧 PA0/PA1 直接接 USB-A 座，Probe 侧 PA0/PA1 引到排针 H101（Pin2/Pin3）。
- **进入 Bootloader 的条件**（满足其一）：① 空片——Flash 0 地址为擦除态（`0xFFFFFFFF`）时上电停留 ISP 不跳转；② 上电瞬间把 PA1 拉高（串口免按键，握手窗口约 40ms）；③ USB 总线满足 `UDP(D+) 高 & UDM(D-) 低`。ISP 引脚/总线检测仅在**上电复位后**进行。
- **首次烧录**：空片直接连 USB（Dongle）或按 H101 接线（Probe），WCHISPTool 即可识别下载。
- **Dongle 二次烧录（`CMD:DFU`）**：Dongle 枚举为虚拟串口后，向 COM2 发 `CMD:DFU`，固件擦除 Flash 第 0 扇区（抹掉复位向量）并软复位，芯片因 0 地址为空重新驻留 Bootloader；若未被立即识别，**拔插一次 USB**（冷启动触发检测）后用 WCHISPTool 重新下载（新固件会重写第 0 扇区）。
- **Probe 二次烧录**：Probe 无板载 USB 到芯片，需经 H101 临时接 USB 线（D-→Pin2、D+→Pin3、GND→Pin4）或 USB-TTL，并在上电瞬间拉高 PA1 进入串口 ISP；进入 Bootloader 后 2.4G 射频停摆，必须保持物理连接才能下载。
- 复位/烧录阶段引脚由 ROM 用作 ISP，用户固件运行后才复用为 UART/USB，故烧录与运行时功能不冲突。

### 5.7 上位机（两套，功能对等）

- **`app_win/`（Windows GUI）**：Dear ImGui + DirectX11 + C++/WinRT(BLE) + SetupAPI，实时绘制电流/功率/电压曲线、串口透传、一键复位/进烧录/查版本；连接 COM2 后自动查询并在状态栏显示两端固件版本。CMake + MSVC(VS2022) 构建，产物 `CH570_Monitor.exe`。
- **`app_linux/`（Linux 终端 TUI）**：`ch570mon`，C + ncursesw，htop 风格单线程 TUI，块字符 sparkline 画 I/P/V，下方串口透传回滚，按键复位/进烧录/查版本等；`make` 构建（依赖 `libncursesw5-dev`）。
- 两者均复用 COM2 的 ASCII 文本协议（见 5.3），无需额外固件支持。仓库的 GitHub Actions 会为 Windows 与 Linux（x64 / aarch64）自动构建上位机产物，并对固件做编译校验。
