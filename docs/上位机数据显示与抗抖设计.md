# 上位机数据显示与抗抖设计

## 1. 目标

上位机同时承担实时显示、曲线绘制、CSV 记录和设备控制。实时卡片需要易读、稳定，曲线和 CSV 需要保留设备上报的原始数据，不能因为显示滤波而丢失测量信息。

因此系统将数据分成两条路径：

```text
串口/BLE 原始报文
        |
        +--> TelemetryHistory（15min 原始，较早 1Hz） --> 曲线、min/max、积分
        |
        +--> 最近 3 个采样点中值 --> 时间常数 EMA --> 卡片实时数字
```

## 2. 实时卡片滤波

每当 `TelemetryHistory` 出现一个新的采样时间戳时，卡片滤波器只计算一次，和 ImGui 的绘制帧率无关。

1. 取当前点和之前最多两个点。
2. 对电流、电压、功率分别取三点中值。这样可以拒绝一个孤立的毛刺，而不会像滑动平均一样把阶跃响应拖得很长。
3. 对中值结果使用一阶 EMA，时间常数约为 0.8 s：

   `y = y + (x - y) * (1 - exp(-dt / 0.8))`

   其中 `dt` 来自设备采样时间戳，不是窗口刷新时间。
4. 只有卡片数字使用滤波结果；15 分钟内曲线、CSV 和统计使用原始采样，长时间曲线使用 1 Hz 趋势点。

如果需要进一步降低跳动，可将时间常数调到 1.0 s；如果需要更快的阶跃响应，可调到 0.5 s。建议每次只改一个参数并用同一段原始 CSV 对比。

## 3. 单位和有效位数

单位切换使用回差，避免数值在边界附近来回跳变：

| 项目 | 进入大单位 | 返回小单位 |
| --- | ---: | ---: |
| 电流 | 1.50 A | 1.35 A |
| 电压 | 2.00 V | 1.80 V |
| 功率 | 1.00 W | 0.85 W |

大单位下仍保留固定的小数位：电流 A 取 3 位，电压 V 取 3 位，功率 W 取 3 位。小单位继续使用 mA、mV、mW。单位切换不会缩短原始数据的精度，CSV 始终写入原始浮点值。

## 4. 累计电量和能量

积分在 `TelemetryHistory` 中以 Ah/Wh 进行，显示时转换为 mAh/mWh。显示字段扩展为 6 个数字槽，并保留 3 位小数。积分只使用有效时间间隔，异常的大间隔会被丢弃，避免断线时间被误算成耗电量。

## 5. CSV 记录

CSV 是原始数据记录，不应用卡片滤波。每行包含：

`timestamp_ms,time,current_mA,voltage_V,power_mW,capacity_mAh,energy_mWh`

记录按照用户选择的时间间隔抽取，每小时自动换文件，文件名为 `record_YYYYMMDDHHMMSS.csv`。文件使用单个 `\n` 行结束，避免 Windows 文本模式再次转换成空行。

## 6. 验收条件

- 同一份原始 CSV 重放时，卡片显示不应随窗口帧率改变。
- 单个异常尖峰只影响曲线和 min/max，不应让卡片数字瞬间跳到尖峰值。
- 在 1.50A、2.00V、1.00W 附近缓慢变化时，单位不能快速来回切换。
- 暂停采集后卡片保持最后一次值，继续采集后从新的采样时间戳继续滤波。
- CSV 行数和设备上报的时间间隔一致，不出现空白行，原始小数精度不因显示格式改变。
